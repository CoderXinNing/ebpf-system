[P1.9] Agent 自身 + 系统日常行为误报
=================================================
创建：2026-10-08
状态：待处理
=================================================

【现状】

触发源（/etc/passwd 被读的 12 处/采集周期，优化后）：
- agent        1 次（自身资产采集，已优化但仍有 1 次）
- whoami       1 次（agent_self.go 的 exec.Command("whoami")）
- bash         1 次（用户手动）
- cron         9 次（系统定时任务）

系统进程（每 5 分钟）：
- cron / anacron / logrotate 读 /etc/passwd、/etc/shadow
- 都触发"密码文件读取"告警

Agent 子进程（每采集周期）：
- last / dpkg-query / rpm / systemctl / pip / npm 等
- 读 /etc/passwd 或触发 exec 告警

结果：告警列表被自身/系统行为污染


【方案 A（推荐）】进程树 + 规则双管

A1. Agent 自身进程树过滤（C 层）
    原理：
    - Agent 启动时把自己 PID 写入 C map: agent_pids
    - C 层 sched_process_fork hook 跟随，子进程自动继承标记
    - file_access / exec / bash hook: pid ∈ agent_pids → 丢弃
    - 复用 G2 的进程树基础设施
    - PID 复用防护：用 (pid, start_time) 双因子（防 PID 复用攻击）
    
    优点：
    - 精准（内核态判定，防 comm 伪造）
    - 一次过滤所有探针
    - 不依赖规则内容
    
    工作量：半天
    依赖：无
    风险：sched_process_fork 全机触发（但只一次 map lookup，< 100ns）

A2. 规则加 exclude_comms（规则层）
    原理：
    - RuleSet.SensitivePaths 加 exclude_comms []string
    - 例：["cron", "logrotate", "anacron"]
    - C 层或 Agent 层过滤
    
    优点：
    - 灵活（Server 下发，运维可配）
    - 不依赖 C 层改动
    
    风险：
    - comm 可伪造（exec -a cron cat /etc/shadow）
    - 只对"低危路径"生效（/etc/passwd 不告警）
    - 高敏路径（/etc/shadow）仍告警
    
    工作量：半天
    依赖：敏感路径动态化（已完成阶段 1-3）


【方案 B】等编排引擎
- Agent 作为非画像进程，天然被过滤
- 系统进程同理
- 但要等 2-3 周
- 见 docs/orchestration-engine.txt


【方案 C】告警降级
- /etc/passwd 从 high 降级为 low
- 简单但治标
- 治本仍需 A 或 B


【推荐执行顺序】

第一步：A1（半天）
- 减少 90% Agent 自身噪声
- 剩下系统进程噪声（cron/logrotate）

第二步：A2（半天，按需）
- 减少 cron/logrotate 噪声
- 但要考虑 comm 伪造风险

第三步：编排引擎（2-3 周）
- 治本
- Agent + 系统进程 + 业务进程 全部分类


【关联任务】

- G2 星轨进程树（已完成）：提供 pid→ppid 映射
- 敏感路径动态化（已完成阶段 1-3）：提供规则下发能力
- 编排引擎（未开工）：会自然解决，但要等

【优先级】P1（不阻塞主流程，但影响告警质量）

【验收标准】
- 采集周期内，Agent 自身/系统进程产生的事件不触发告警
- 真实攻击（如攻击者读 /etc/shadow）仍正常告警
